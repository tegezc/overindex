How a report is built

A fixed sequence. The model does not choose the tools.

Start

Browser

A podcast name, or a featured report already saved on the server.

App

Next.js on one VM

The page and the API are one app on Compute Engine. A live report streams over SSE. The API key stays on the server.

No new calls

Featured report

Read from disk. Opening one does not call Qloo and does not start a live report.

Live report

Fixed orchestrator

Target 25 Qloo calls. Hard cap 40. Past the plan, the candidate section is marked partial.

Taste graph

Qloo harness 0.1.26

Workflows: describe, entity tags, demographics, and recommend for artist, TV show, movie, and book.

Insights: two popularity bands, scores for the shared candidate set, and a baseline from a fixed basket of eight podcasts.

Calls run only when the base URL is hackathon.api.qloo.com.

Two structured steps

Language model

Narrow a show match when more than one candidate is plausible.

Write the Without Qloo list from the show name and a description. That step does not receive affinity scores.

On the server

Scoring and pitch

Percentile, lane, and quadrant. Fit equals the show's affinity percentile.

The pitch is built from evidence already on the report. It does not call a model. Numbers that are not in the evidence are dropped.

Not called: rank, audience compare, and trends.
